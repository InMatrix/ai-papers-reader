title: Grounding AI Coding Agents in a Live Platform Could Make Data Pipelines More
  Editable, Researchers Report
---



Coding agents can turn a plain-language request into a working data-processing script in minutes, but the result is often a one-off file that sits outside the tools teams use to inspect and revise their workflows. Researchers from Peking University and collaborating institutions call this disconnect the "NL2Pipeline gap." In a new arXiv paper, they describe DataFlow-Harness, a system that tries to close it by having an agent build a persistent, platform-native pipeline instead of a script.

The pipeline is represented as a directed acyclic graph (DAG), a set of data operators connected by dependencies with no loops. The system has three parts. DataFlow-Skills supplies procedural guidance, such as recommended steps for inferring schemas, choosing operators, and configuring parameters. A Model Context Protocol (MCP) layer, an open standard for connecting AI tools to external systems, gives the agent live access to the operator registry and the current pipeline state. The agent makes small, typed changes, such as adding an operator or connecting two of them, and each change is committed only if the graph remains acyclic and adjacent operators have compatible fields. A web interface keeps a chat panel and a visual graph editor synchronized, so a user's manual edits are visible to the agent on its next turn.

The authors offer an example of why grounding matters. Given a dataset of question-answer records, the agent noticed that a downstream evaluator needed scalar question and answer fields and could not read a nested list of pairs directly. It planned to expand that list into one row per pair before evaluation.

On a 12-task benchmark, with each task run 10 times per method using Claude Opus 4.7, DataFlow-Harness achieved a 93.3% end-to-end pass rate. Vanilla Claude Code, which writes disposable Python scripts without platform context, reached 91.7%. A Context-Aware variant that was given the raw codebase reached 94.2%. An MCP-only configuration, lacking Skills, reached 83.3%. Harness therefore scored 10.0 percentage points above MCP-only and 0.9 points below Context-Aware, a gap the authors do not describe as statistical equivalence. Relative to Vanilla, Harness reduced measured cost by 72.5%, from $0.950 to $0.261, and latency by 49.9%, from 190.7 to 95.5 seconds. Against Context-Aware, it lowered cost by 42.8% and latency by 17.6%. The authors attribute much of the savings to lower token consumption.

The per-task breakdown offers a clue about where Skills help. On three question-answering tasks that depend on implicit procedure, MCP-only passed 6 of 10 trials on basic QA, while Harness passed 10 of 10. Simple routing tasks showed no difference, and two multi-field scoring tasks failed equally often at 7 of 10, which the authors attribute to numerical constraint violations rather than workflow construction.

Two downstream case studies also favored agent-authored pipelines built with the harness. Training Qwen2.5-32B-Instruct on data from one math pipeline raised the nine-benchmark average from 54.5 to 55.7 after two epochs, and from 49.9 to 51.6 after one. A general instruction-tuning pipeline for Qwen2.5-7B-Base produced an average of 63.8 versus 61.5.

The authors acknowledge important limits. The evaluation uses one agent and model family and a small, platform-specific benchmark. The results lack confidence intervals, and schema validation cannot guarantee semantic correctness. Ablations do not isolate validation, and the two training studies each compare a single pipeline per arm. Persistence, concurrent editing, and recovery were not tested.

The work suggests that tying an agent to a platform's live metadata and procedures may matter as much as the underlying model for building maintainable data workflows. Whether those gains hold across other platforms and models remains an open question.
