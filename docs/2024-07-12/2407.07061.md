title: Researchers Propose an "Internet of Agents" to Let Separately Built AI Systems
  Collaborate
---



Large language models have made it possible to build AI "agents" that break tasks into steps, use tools, and learn from feedback. Many of these agents, however, are built within closed ecosystems, and existing multi-agent frameworks often struggle to combine agents from different developers. Most also run on a single machine and follow fixed communication scripts. A team from Tsinghua University, Peking University, Beijing University of Posts and Telecommunications, and Tencent argues that these limits make it hard for agents with different skills to tackle complex work together. In a work-in-progress paper, they propose a remedy called the Internet of Agents (IoA).

The design borrows from instant messaging. Each agent connects through a client wrapper to a central server, which maintains a registry of agents and their described capabilities. An agent facing a task can search the registry for collaborators and open a group chat. Groups can spawn sub-groups, which the authors call nested teams. Conversations move through five states: discussion, synchronous task assignment (the chat pauses until the task finishes), asynchronous task assignment (work proceeds alongside discussion), pause-and-trigger, and conclusion. The language model inside each agent chooses the next state and the next speaker. The authors describe this as a finite-state machine, a system with a fixed set of states and rules for moving between them, except that the model, not a programmer, makes the transition decisions.

The paper offers an example of nested teaming. In a walkthrough of a research-paper task, a coordinating agent forms a group that includes a literature-review agent. When that agent identifies a need for PDF expertise, it opens a sub-group and brings in a PDF agent.

The authors report several results. On the validation set of GAIA, a benchmark of multi-step questions, IoA built from four basic ReAct agents (simple reason-and-act agents, each with one tool) scored 40.00 overall. AutoGen scored 39.39, FRIDAY 34.55, and GPT-4 6.06. AutoGen did better on the easiest level. In open-ended tasks judged by GPT-4, IoA won 76.5% of comparisons against AutoGPT and 63.4% against Open Interpreter. These are win rates, not score gains, and a "win" required the judge to prefer one response in both presentation orders. On RoCoBench, a set of embodied robot-coordination tasks, IoA achieved a 1.00 success rate on three of five tasks, where the Roco Dialog baseline scored 0.70 to 0.75. In retrieval-augmented question answering, a GPT-3.5-based IoA with three agents scored 0.671 overall, compared with 0.611 for GPT-4.

The study also documents costs. Running AutoGPT inside IoA lowered its per-task cost from $0.39 to $0.33, but the conversation among agents added $0.53, bringing the total to $0.99. The authors observed agents repeating or rephrasing earlier messages, and sometimes failing to switch to the pause state. Removing these repetitions cut communication costs by nearly half. The authors suggest that current models are tuned as chatbots rather than efficient communicators.

These findings come from benchmarks the authors selected or designed, several evaluated by an LLM judge, and the paper does not report agents running across physical devices. Still, the work points toward a messaging-style layer that could let independently built agents cooperate. Whether such systems can be made affordable and reliable outside controlled tests remains an open question.
