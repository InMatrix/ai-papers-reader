title: Plain-Language Robot Programming Gets a ROS Framework, With Caveats
---



Programming a robot for a new task usually means calling in engineers who can write and reconfigure its software. That bottleneck slows adoption in homes, healthcare, and construction, where tasks change often. A research team led by Huawei Noah's Ark Lab, with collaborators at several universities and ETH Zurich, reports a framework that lets non-experts describe tasks in ordinary language instead.

The system, called ROS-LLM, connects a large language model (LLM), a text-based AI system, to the Robot Operating System (ROS), an open-source software framework widely used in robotics. Developers supply a library of "atomic actions," basic skills such as reaching, grasping, or switching on a coffee machine, each with a short text description. A user types a request into a chat interface. The framework combines that request with text summaries of sensor readings and any earlier feedback, then asks the LLM to produce a behavior. That output can be an ordered sequence of actions, an XML behavior tree, or Python code. Users can also teach new skills by guiding the arm by hand or by teleoperation, which the system encodes using dynamic movement primitives, a method for learning smooth motions from a few demonstrations.

The authors illustrate the correction loop with a failure during a cube task. The robot could not find its target cube because its own arm blocked the camera. The human operator typed, "Please home the arm before looking for the cube." The authors argue that feedback naming the correct action works better than feedback that only identifies a mistake, such as "Pick up the blue cube first, then place it on the green cube," rather than "You picked up the cube in a wrong order."

The main experiments used Deepseek 7B Coder, an open-source model hosted on a server in Europe, to control a Universal Robots UR5 arm in Asia. The robot carried out a twelve-step "make me a coffee" sequence, though the paper describes this result qualitatively rather than with success rates. The more quantitative test was a tabletop rearrangement task with two to eight boxes, five tasks per box count, 35 in total. By the authors' bar chart, the LLM alone succeeded on roughly 16 tasks on its first attempt, about 46 percent. After human feedback, roughly 23 succeeded, about 66 percent, a gain of around 20 percentage points. The authors say success "can be maintained" as complexity grows, but the sample is small, and the chart shows no steady pattern across box counts.

In a remote-control study, seven volunteers in Europe guided the robot in Asia through pick-and-place tasks, with a 2–3 second network lag. Average completion times were 6 minutes 9 seconds for the first task and 9 minutes for the second, though individual times ranged widely. Participants' NASA Task Load Index ratings for mental, physical, and temporal demand were similar.

The paper is candid about its limits. Minor wording changes, such as "another cube" versus "the other cube," sometimes changed the generated actions. Example sequences in prompts sometimes led the model to act on objects that were not present. Operators issued ambiguous commands, and the robot occasionally repeated or misinterpreted instructions. The system also depends on hard-coded failure indicators, such as a gripper width of zero, and feedback is text-only. The behavior-tree interface had not yet been tested experimentally. The paper compares the framework to related work in a feature table but offers no head-to-head performance benchmark.

The work suggests that open-source LLMs running on modest hardware can translate plain-language requests into multistep robot behavior, with human feedback improving outcomes. Yet the evidence comes from one laboratory setup, a single model, and a few dozen tasks. Whether the approach generalizes to other robots and environments remains an open question.
