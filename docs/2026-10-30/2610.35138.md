title: Coding Agents Meet Most Criteria in Real Design Requests but Fully Complete
  Few
---



Users increasingly ask coding agents to revise working software by pointing at a screenshot, uploading a recording, or describing a change that spans several files. A new benchmark called Co-Design Bench suggests that agents can satisfy much of such a request while still leaving parts of it undone, a gap that single pass-or-fail scores can obscure.

The benchmark, described by researchers from Alibaba Token Hub and several universities, contains 273 tasks drawn from 37,463 deduplicated queries across 26,314 real user coding sessions. Each task pairs a runnable pre-edit web application with a user request and hidden acceptance criteria written by experts, 2,331 in total. The tasks fall into two tracks. Multimodal Editing (ME), with 100 tasks, involves localized changes that may include an image, audio clip, video, or document. Repository Editing (RE), with 173 tasks, requires coordinated changes across components, routes, and application state in multi-file frontend projects.

To grade the results, the authors use what they call a judge-then-refute protocol. A primary evaluator, an AI model, marks each criterion as PASS, PARTIAL, or FAIL using source code, rendered pages, and recorded browser actions. A separate language-model verifier then challenges positive verdicts, looking for stubs, hardcoded outputs, and unreachable features. Visual and interaction claims must be supported by screenshots or browser logs. The authors acknowledge that this process reduces unsupported credit but "cannot eliminate judgment error."

The paper's example is a sports clip editor. The user asks for clips to be added with limits on count and duration, for timeline markers to stay aligned when the view is zoomed, and for the add function to become available again after clips are removed or split. Because these requirements depend on one another, the task succeeds only if the application's behavior holds across all of them.

Ten model endpoints were tested under a shared agentic harness, meaning the agent could inspect, edit, build, and run the application. The strongest, gpt-6-astra, averaged a strict completion score of 0.699, or 69.9%, across all tasks, meaning it passed roughly 70% of criteria per task on average. Yet only 26.4% of tasks were fully passed. On ME its strict score was 0.754 with a 41.0% full-pass rate, and on RE it was 0.667 with 17.9%. The authors report that the same model also led both tracks in strict completion, although rankings of other models shifted between tracks.

Edit breadth also mattered. Tasks requiring three or four types of change averaged 0.591 strict completion, compared with 0.654 for tasks with one or two types, a gap of 6.3 percentage points. Every endpoint scored lower on the broader tasks. Full-pass rates, however, were similar, at 9.1% and 9.7%.

Agentic execution also affected scores. On 150 WebCompass-edit tasks from a separate benchmark, the qwen3.7-plus model rose from 73.6% under single-shot prompting to 95.1% with agentic execution, a gain of 21.5 percentage points. The authors caution that cross-benchmark comparisons use different tasks and protocols.

Several limits constrain these findings. Requests are fixed, with no simulated user feedback during execution. Costs are reported as token counts rather than money, and the main comparison uses a single harness. Experts checked 200 task-model outputs, but the grading remains partly dependent on language models.

The study's main contribution is methodological: it separates criterion coverage from complete delivery. Its results indicate that partial success is common, but they do not establish how well agents would perform with real users in the loop.
