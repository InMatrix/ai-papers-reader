title: To Build Software From Scratch, AI Agents Need a Requirements Phase
---



Ask an AI coding agent to fix a bug in a large codebase and it often shines. Ask it to rebuild a nontrivial command-line tool from nothing but its README and a compiled binary, and it mostly flounders. On the ProgramBench benchmark, even frontier models fully reconstruct fewer than 1% of target programs. A new paper argues that the missing ingredient is an old-school software engineering discipline: writing down what the program should do before coding starts.

The researchers propose SpecFirst, a two-stage framework that splits the task into a dedicated “spec agent” and a separate code-synthesis agent. The spec agent first probes the execute-only binary with carefully chosen inputs—empty strings, malformed flags, flag combinations, adjacent outputs—and distills its observations into a structured behavioral specification called SPEC.md. Only then does a code-synthesis agent read that document and begin implementation.

The contrast with existing agents is stark. Current frameworks like SWE-agent and OpenHands mix probing, reading, planning, and coding into one undifferentiated loop. That entanglement causes three systematic failures, according to the paper. Agents stop probing too early. They lose behavioral details over long runs as context drifts. And a single early misinterpretation can silently corrupt every later decision.

The paper illustrates these failures with gomplate, a Go template renderer used in ProgramBench. Its README mentions a handful of flags and namespaces, but the real binary exposes dozens of built-in functions across namespaces like coll, math, net, crypto, and strings. In one run, a GPT-5.5-high agent collected a full namespace index at turn 4, then never referenced six of those namespaces again—causing 126 test failures before any code was written for them. In another run, a model correctly read the typed signature of a math function called Seq, then implemented a degraded version with untyped arguments. Over 140 turns, the math namespace was refactored five times, each time re-emitting the wrong signature, and 25 of 43 Seq tests failed with type errors.

SpecFirst directly attacks all three failure modes. The dedicated spec agent is forced to explore before implementation, so edge cases and error paths get documented instead of guessed. The persistent SPEC.md acts as an external anchor, so knowledge does not evaporate as context grows. And because the spec is written down, a wrong assumption is more likely to be caught rather than compounded.

The empirical results are consistent. Across all 200 ProgramBench instances and four models—Qwen3.5-397B, Qwen3.6-35B, GPT-5.5-high, and GPT-5.4-mini—SpecFirst improved average test pass rates by 6.9% to 21.3% and binary exploration coverage by 9.4% to 18.5%. The gains were statistically significant in every setting. Perhaps most striking, SpecFirst tripled the rate of near-perfect solutions: with GPT-5.5-high, the share of programs passing at least 90% of tests rose from 5.5% to 16.5%.

The paper’s deeper message is that “requirements elicitation” is not a bureaucratic extra step. For AI agents, it is a cognitive scaffold that turns a hopeless long-horizon guessing game into a tractable engineering task.
